# 3つの段階で何を見るか

判断が要るところだけをここに集めた．
機械で測れることは各スクリプトが出力に書くので，ここには**目で見る点**を書く．

## 段階1 — 格子(`overlay.png`)

画像を Read して，上から順に見る．

### 1. 段の数と表の数

**段と表を取り違えない**．

| | 並び方 | 中身 | 扱い |
|:---|:---|:---|:---|
| **段** | 横 | 縦に長い表を左右に折り返したもの．**地点は同じ** | 1つの表にまとめる |
| **表** | 縦 | **別の表**．表頭も地点も違う | 最後まで別々に扱う |

段のある資料は**3割**，表が2つ以上あるページは手元で**1枚だけ**(kinki_037)．

- `summary.txt` の「段: N」と，画像の見た目が合っているか
- 段が1つに見えるのに `col` の紫の枠が左右に離れて2群あるなら，
  種名の列(`species_col` / `sname`)が右の段で検出されていない．
  段として認識されていない徴候(隣の段に吸収される)
- 表が2つ以上あるページは，置き場が `work/<画像名>_t1/`・`_t2/` に分かれ，
  **overlay もそれぞれに出る**．片方の overlay に他方の表の格子が
  写り込んでいたら，切る位置(2つ目の表頭の上端)を間違えている
- 左右に並んだ表は，部分画像に切り出してやり直すので置き場が
  `_s1/`・`_s2/`(縦にも分かれれば `_s1p1/`・`_s1p2/`)になる．
  **同じ表が2つの置き場に出ていないか**(切り出しの縦の範囲が隣の表まで
  及ぶと，同じ表が写しとして組み上がる)と，**切れ目の列が欠けていないか**を見る

### 2. 色の付いた枠

| 色 | 意味 | 見方 |
|:---|:---|:---|
| 赤(太) | `on_text` ずらしても文字に重なったまま | **必ず見る**．文字が2つのセルに割れる |
| 橙(太) | `snapped` 文字を避けてずらした | 移動先が正しいか．隣の行へ飛んでいないか |
| 金(太) | `interpolated` 検出漏れを内挿した | その行が**実際に空行**なら正しい |

金色が多いのは，それだけで誤りではない．
`example.jpg` では内挿した3行がすべて実際の空行だった．
**画像を見て，そこに行があるかを確かめる**．

### 3. 行番号・列番号

`overlay.png` には CSV の `row` / `col` と同じ番号が焼いてある．

- 組成部の行番号が，表の行と1対1に対応しているか
  (ずれていたら，どこから2つに割れたか / まとまったかを言えるようにする)
- 番号は表頭のセルにも振られるので，組成部は途中の番号から始まる(それでよい)

### 4. 検出されなかったクラス

`summary.txt` の「← 検出なし」を見る．

- **`layer` が無い** — 階層の列が**そもそも無い表**が半分以上ある
  (草原・海岸砂丘など)．画像を見て列が無ければ，これは正しい結果
- **`once_species` が無い** — 表の下に段落が見えるのに検出されていないなら，
  それが「調査地の記載」の可能性がある(読んで判別する)
- **`header` が無い** — 表頭が切り出せない．`--conf` を下げて確かめる

### 通ってよい条件

赤が0，段の数が見た目と合い，行番号が表の行と対応していること．
金・橙は，画像で確かめたうえなら通してよい．

## 段階2 — 読み取り(`crops/`)

### 文章の領域(`region_*.png`)

丸ごと読んで1つの文字列にする．改行は空白にして，読み順につなぐ．

- **1回出現種**: `in N :` で地点が変わり，カンマで種が区切られる．
  各項目は「学名 和名 (階層—)被度」．
  **段落の終わりに注意**．列挙のあとに `Lage d. Aufn.` が続くことがある
  (`kinki_017` は最終行の末尾に混じる)．混じったら，その部分は書かない
- **文章形式の表頭**: 「項目：値」の並び．表題(`Tab. 85. …`)が頭に付いていてよい
  (構文解析が無視する)．`方位及び傾斜：S 2°` のように2項目で値を共有する形はそのまま書く

### 小さいセル(`sheet_*.png`)

`#cell_id` が焼いてある．読めたものだけ TSV に書く．

- **読めないものは書かない**．無理に埋めると，あとから気づけない誤りになる
- 迷ったら書かずに `Need Check` のまま残し，最後にユーザーへ伝える
- 書式は `references/reading-guide.md`

### 読み直しても直らないとき

`apply_text.py` が `Need Check` のまま返したら，切り出しがずれている可能性がある．
`overlay.png` のその行・列を見て，境界が文字に乗っていないか確かめる．
乗っていれば段階1に戻る．

## 段階3 — 検査(`checks.txt`)

検査は**徴候を挙げるだけ**．誤りかどうかは画像で決める．

| 検査 | 引っかかったら |
|:---|:---|
| 地点番号の超過 | 目印(`in N :`)の読み違え．領域を読み直す |
| 同じ地点に同じ種 | **階層が違えば正当**(高木層と低木層に同じ種)．同じなら1種が2件に割れている |
| 被度として読めない形 | その `cell_id` を切り出して読み直す |
| 表頭で読めていない項目 | 領域を読み直す．小数点の読み落としは**直さない** |
| `note` の付いた行 | 段階1で確かめてあれば通してよい |

### 最後にユーザーへ伝えること

- 何行取れたか(`body` / `once` の内訳)，地点数，種数
- `Need Check` が何件残ったか．**残ったことを黙らない**
- 目視で直したセルの数(`read_by` が `ai` の件数)
- 判断したこと(段落が1回出現種か調査地の記載か，表頭の形式)

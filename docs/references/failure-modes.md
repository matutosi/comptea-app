# 既知の崩れ方と直し方

実データで確かめたものだけを書く．推測は書かない．
出典は `.claude/CLAUDE.md` の進捗の記録．

## 検出(関門1)

### 「このページに組成表が見あたらない」で止まる

**多くはそのとおりで，直す必要がない**．
手元の資料(近畿の 88 枚)には，本文・写真・隣のページから続く
「1回出現種」や調査地の流し込みだけのページが **9 枚**混ざっていた
(kinki_005, 011, 046, 051, 062, 064, 073, 080, 082．2026-09-01 に全枚数を目で確認)．

- 検出が0件になるか，枠がいくつか出るだけで組成セルを作れない
- 判定は `locate.looks_like_no_table()`．
  **組成セルが1つも無く，`col` が1本も無く，`row` が5本未満**のときだけ表でないとみなす
- **本物の表なのに `col` が取れない段**(旧 kinki_047 の型)は，この判定に引っかからない．
  ページのどこかに組成セルが1つでもあれば表として扱う

表が写っているのに止まるなら `--conf-col` を下げる．

### 行が異常に多い / 最後の行が異常に高い

検出が1本でも離れたところに紛れると，そこまでの隙間を内挿で埋めていた
(`kinki_007` はページ最上部の誤検出1本で 6行が52行になった)．
いまは `locate._drop_isolated()` が離れた塊を捨て，警告に出す．
それでも多いときは，`overlay.png` で内挿された行が本当に空行かを見る．
捨てた箱は**両端の境からも外す**(2026-09-04)．中心の並びからだけ捨てていたので，
流し込みの中の 1 本の下端が最後の行の下端になり，最後の行が 1,487 px になっていた
(`s01115_02_p1_s1`)．「行の高さが極端に不揃い」の警告はこれで見つかる．

### 列が検出されない / 少ない

- **`--conf-col` を下げても直らないことがある**．
  `kinki_047` の左の段は conf 0.05 でも検出されなかった．閾値の問題ではない
- 逆に**下げすぎない**．0.30 が折れ点で，下げると境界が文字に乗る割合が急に悪化する
- `col` が1本しかない資料(1地点の表)は正常．そのまま1列として扱う

### `--conf` の目安

| 値 | どうなるか |
|---:|:---|
| 0.15 | 行は4%増えるが，境界が文字に乗る割合が倍になる．下げすぎ |
| **0.30** | 既定．学習外を含む77枚で決めた折れ点 |
| 0.60 | 行を12%取りこぼす．境界の質は改善しない．高すぎ |

**モデルと推論の `imgsz` は必ず揃える**．`weights/comptea.pt` は 1280 で学習した．
640 で推論すると行の一致が 7/7 から 3/7 に落ちる．

### 表頭の中に行が検出される

`locate.drop_rows_outside_body()` が，表頭や1回出現種の領域に半分以上入った
`row` を捨てる．領域そのものが検出できていれば，これで直る．
直らないなら `header` / `once_species` が検出されていない．

### 表頭の直下の種群が落ちる

`row` の最初の検出が表の途中にあると，格子も谷を数える範囲もそこから下だけに
なり，表頭の直下の種群が黙って落ちていた(折り込みの 68 表中 28 表・約 371 行．
`s01115_15_p2` は 65 行．2026-09-04)．行の検査も同じ範囲で数えていたので鳴らない．
いまは `split_wide.body_extent()` が上端も `col` の検出から取り，表頭の下で切る．
関門1では**表頭の直下の行が格子に入っているか**を必ず見る．
「表頭の値の行 N 行が組成部の中にある」が出たら，項目行の誤検出が組成部の行を
表頭として切っている(`drop_stray_plot_rows()` が捨てるはずのもの)．

### 行が割れすぎる / 繋がる

行を黒画素から決め直すときは，**行の高さは 1 つの表の中でほぼ一定**という性質を
使う(2026-09-04 ユーザ指摘)．谷をそのまま行にすると「・」だけの行が数行まとめて
1 つの谷になり(08_p1)，汚れや破線で 1 つの行間が 3 つに割れる(kinki_034 は
21 行の表が 30 行)．いまは黒画素の自己相関で行の高さを求め，その高さで進みながら
境を黒画素の最小に寄せる(`split_wide.expected_row_edges()`)．警告に「行の高さ N px」
と出るので，**関門1でその値が 1 行分か**を見る(2 行分なら組成部と種名の両方で
2 倍に化けている珍しい表)．

### 行の境が片端で字を割る(紙面の傾き)

折り込みは最大 1° ほど傾いてスキャンされており，組成部の左端と右端で行が
行の高さの 0.3-1.0 倍ずれる表が 9 つある(08_p2 は −0.83°)．水平な境では
どうやっても片端で `2.2` が上下に割れる．いまは `deskew.py` が組成部の左右の
黒画素の並びのずれから角度を測り，**ずれが行の 0.3 倍以上**のときだけ回して
検出し直す(警告に「紙面の傾き ±X° を直して検出し直した」と出る．座標は
`<作業名>_deskew.png` のもの)．本のページ(88 枚)は 0.03 倍で発動しない．

### 種名の列が検出されない

`sname`・`species_col` が 0 件なら，`name_col.py` が組成部の左の黒画素の山と谷から
学名(左)・和名(右)の箱を作り，「黒画素の帯から補った」と警告に出す．
関門1で列の位置を目で確かめる．帯が 1 本なら和名とみなしているので，
読んだ中身がラテン文字なら学名の列だった．

### 罫線

境界のインク量が多くても，山の幅が狭ければ罫線とみなして
その中央に合わせる(谷へ逃がさない)．
罫線に合わせたものは `snapped` に数えないので，橙が出ていなければ正常．

## OCR(関門2)

### 値のあるセルが Need Check になる(タイプ打ちの数字)

タイプ打ちの折り込みでは EasyOCR が `2.2` を `ムっム`，`+.2` を `十・ム` と読む
(08_p2 は組成部の 35 セル)．いまは値として通らなかった組成部のセルを
**字種を `0-9 + r ・` に絞って読み直す**(35 → 7)．ただし絞ると `+` を `4` と
読むことがあるので，差し替えたセルは `note` に `retry` が付いて目視に回る．
セルを横切る**横の枠線**は読む前に消す(example.jpg の `+` が `4` に化けていた)．
**縦線は消さない**(タイプ打ちの `1` まで消えた．ユーザ指示 2026-09-04)．

EasyOCR がよく崩す形．**切り出しの位置が正しくても起きる**ので，
関門1へ戻る前にこちらを疑う．

| 崩れ方 | 例 | 備考 |
|:---|:---|:---|
| `%` `°` が `9` | `50%` → `509` | 範囲(被度0-100，傾斜0-90)で弾ける |
| `O` と `0` | `SO` → `S0`，`IOOm²` → 100m² | `correct_field_no` が先頭2文字を接頭辞として戻す |
| 小数点の読み落とし | `0.6` → `0 6` | **直さない**．`6` かもしれない．`Need Check` で目視へ |
| `+` が漢数字 | `+` → `十` | 補正が受け付ける |
| 階層の区切りが漢数字 | `K・1・2` → `K一1・2` | 同上 |
| 被度の区切りが消える | `+・2` → `十2` | `+ r 十` のときだけ区切りを省略可 |
| 中黒がカンマに | `+・2` → `+,2` | 1回出現種で種が2件に割れる原因だった |
| `var.` の `.` がカンマに | `var.` → `var,` | 残った `r` が被度と誤認された |
| 和名が行またぎで割れる | `ク` + `ロマツ` | カタカナ間の空白を落とす |
| 地点の目印が読めない | `in6` → `inG` | そこで切れず，地点番号が前のままになる |

### 辞書補正の危うさ

**候補が1つの補正は，誤っていても通る**．
`マダイコソ`(= ハマダイコン)が `マダイオウ` になった例がある．
`review.tsv` の `suggested` はこれ．**元の画像を見て確かめる**．

候補が複数のときは `multi` になり，自動では選ばない．

## 表の組み立て(関門3)

### 1回出現種が0件になる

- 領域が検出されていない(関門1で確認)
- 領域は読めているが，`in N :` の目印が崩れて解析が止まった
  → 領域を読み直して `apply_text.py` で入れ直す

### 表頭が空になる

- 表形式なのに `plot_row` が検出されていない → 項目行が取れず，値も出ない
- 文章形式で，`header` 領域が読めていない
- **表形式の表頭を文章として渡してはいけない**．
  格子で読めるものを文章として解釈し，黙って無意味な値が出る
  (`locate.py` は `plot_row` が無いときだけ領域を渡す)

### 被度に `+・2` が出る

**正しい**．`+` や `r` に群度が併記されないという記述は誤りだった
(実データで `+・2` が最頻値)．省略されるのは群度が1のときだけ．
`docs/vegetation_science.md` の記述より，実データを優先する．

## 教訓(同じ失敗を繰り返さないため)

- **7枚で測った結論を信じない**．`row` の閾値を 0.15 にすると7枚では良く見えたが，
  77枚で測ると逆だった(1行に引きずられた過学習)
- **「切られた帯の数」だけを数えない**．列を検出しないほど良く見える．
  反対の失敗(1セルに複数の値)も数える
- **記録した背景知識にも誤りが混じる**．規則に合わない値が最頻値なら，規則を疑う
- **部品が動いても通しでは動かないことがある**．
  試験で領域を直接渡していたため，位置決めの出力に領域が入っていない不具合に
  気づけなかった．**必ず通しで確かめる**
